## 协议与刷新结果

本地 Linux / Go 1.25.1 的无自刷新 helper 已分别验证四个 legacy 修订及 2026-07-28：同一前端连接内，已有 `.go` 与四类依赖文件各连续变化两次，等长且恢复 mtime 后仍由新 PID/boot 读取新输入。helper 的读取次数固定；旧进程直接调用时始终返回旧快照。

其他已运行断言包括：未知正文/字段/schema 和上游错误保留；大整数 ID；部分写入、崩溃、半帧退出和写工具副作用的不重放；旧协议实际 roots 反向交互与状态恢复；现代 MRTR/token、多个长期订阅、取消及 ID 再利用；事件失效、空闲轮询、队列取消；100 轮换代，以及 seed=703031 的 100 步混合故障（71 次独立启动、152 个唯一业务执行，关闭后全部 helper PID 消失）。

真实 gopls 使用固定 v0.24.0。`protobuf v1.34.2 → v1.35.2 → v1.36.6`、内容编辑、新增、删除和原子保存通过，同一 proxy PID 发布了新的后端代次；原生 `tools/list` 直连与代理对照一致。真实后端自身能刷新，因此独立刷新证明仍以受控 helper 为准。

本地执行：

```sh
go vet ./...
go test -race ./...
GOPLS_INTEGRATION=1 GOPLS_BIN=/absolute/path/to/gopls \
  go test ./integration -run '^TestRealGopls' -count=1 -v
bash scripts/build-release.sh dev
```

`-race` 会同时编译带 race 的实际 proxy 子进程，避免只检测测试客户端。发布脚本仅执行本地打包和帮助/版本自检；本次不产生版本 tag 或 Release。

## 审查中修复的问题

独立审查和回归用例促成以下修复：

- 后端写协程按物理连接退出，启动结果通过可取消的所有权交接避免 EOF 时遗留子进程。
- 已取消的有限请求通过有界隔离释放容量；长期订阅独立取消，不误伤同连接其他订阅。
- 扫描绑定开始前已收到的响应和原队首；后到响应、被替换队首不能借用不属于自己的检查点。
- batch 完整交付前重新校验，未交付的协议配置不记作已确认；取消仍能移除缓冲成员。
- 正反向 batch、反向进度和原始 ID 按连接关联；排队、响应、反向分组和长期状态均有限额。
- 通知容量失败显式结束连接；仅已知控制流绕过业务闸门。
- 未知嵌套初始化状态、不确定的已派发协议配置更新，均要求重连。

内容扫描在 Linux amd64、Go 1.25.1、AMD EPYC 9V74、GOMAXPROCS=8 上运行。每档先预热一次，再运行 5 次；文件内容每个 128 bytes。以下是温缓存测量，不是产品 SLA，也不是冷盘吞吐保证。

## 支持边界与验收解释

- 五个具体 profile 的受控后端互通与刷新分别测试；现代夹具不意味着 gopls v0.24.0 原生支持现代协议。
- 原子 batch 的请求成员数不能超过 `max-concurrent`；不会拆成重新分组的业务重放。取消全部排队请求不发送空数组。
- 目录不具备合法失效通知时，只比较已交付的完整分页视图；分页分布或未知字段变化保守重连。
- 非标准初始化扩展、协议版本变更、不可确认的设置恢复失败等会关闭前端；任务、cursor 和不透明 handle 不保证跨进程有效。
- 普通工具已经写文件时，可能收到输入过期错误；副作用不回滚，不提示安全重试。
- 磁盘检查点不构成事务隔离。两次观察之间发生且事件全部丢失的 A→B→A 不能事后检测。
- 本地 root 无法准确模拟非 root 权限拒绝；权限用例在普通 GitHub runner 执行。本地跨编译不替代 macOS 运行结果。
- 冷缓存、真实项目全部方法组合、所有操作系统/文件系统与所有故障排列不在本轮已执行证据内；不得据此声称穷尽兼容。
